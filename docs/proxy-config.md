# API トークンなどの秘匿（プロキシ設定）

フェーズ2 の要件。auto-numbering の API トークンを秘匿し、あわせて秘匿のためだけの汎用プラグイン `api-proxy` を作る。

> **状態: 共有部分（kintone-utils の `secrets`）と auto-numbering は実装済み。api-proxy も実装し、2026-11-23 に実機で確かめた。** 判断の理由は [decisions/proxy-config.md](./decisions/proxy-config.md)。api-proxy の実装の構成は [apps/api-proxy/docs/design.md](../apps/api-proxy/docs/design.md)。

## 前提となる kintone の仕様

| 項目 | 内容 |
| --- | --- |
| 通常のプラグイン設定（`setConfig`） | 実行画面で `getConfig` から読めるため、アプリを使う全員がブラウザで値を見られる。秘密を入れない |
| プロキシ設定の保存（`setProxyConfig(url, method, headers, data, callback)`） | PC のプラグイン設定画面でだけ使える。同じ URL とメソッドの組は上書きされる。`data` の値にオブジェクトは使えない。`callback` を省くとプラグイン一覧の画面に移るため、必ず渡す |
| プロキシ設定の読み込み（`getProxyConfig(url, method)`） | 設定画面でだけ使える。URL とメソッドを指定して1件ずつ読む。保存済みの組を一覧で取る API は無い。ヘッダーの値は文字列で返る |
| プロキシ設定の削除 | API が無い。空のヘッダーと本文（`{}`）で上書きして無効にする |
| 実行（`kintone.plugin.app.proxy(pluginId, url, method, headers, data)`） | PC・モバイルの一覧・詳細・追加・編集などの画面で使える。kintone のサーバーが、保存した値を付けて送る |
| 保存した値が付く条件 | アプリ・プラグイン ID・メソッドが同じで、URL が保存した URL に前方一致（大文字小文字を区別）する。複数が当てはまれば、長く一致したものが使われる。値の重なりは保存した値が優先される。GET・DELETE では保存した本文がクエリ文字列として付く |
| 実行の制限 | メソッドは GET・POST・PUT・DELETE だけ。応答の本文は文字列（10MB まで）で、バイナリは受け取れない。利用者のセッションと Cookie は付かない |
| 同じドメインの kintone REST API | 公式は `kintone.api` を案内している。IP アドレス制限のある環境では kintone の IP を許可する必要があり、推奨されない |
| API トークン | `X-Cybozu-API-Token` にカンマ区切りで9個まで指定できる。トークンでの操作は「Administrator による操作」として記録される |
| 反映のタイミング（2026-11-23 に実機で確認） | 保存した値が `proxy` に付くのは、アプリの設定画面で「アプリを更新」を押した後。押す前は何も付かず、`401 CB_AU01` になる |
| 同じドメインへの `proxy`（2026-11-23 に実機で確認） | 保存した API トークンで、レコードの取得（GET `records.json`）と更新（PUT `record.json`）ができる |
| `proxy` の戻り値（2026-11-23 に実機で確認） | 4xx でも reject されず、`[本文, ステータス, ヘッダー]` で解決する。ステータスは呼び出し側で判定する |

出典: cybozu developer network の [setProxyConfig](https://cybozu.dev/ja/kintone/docs/js-api/plugins/set-config-for-proxy/)・[kintone.plugin.app.proxy](https://cybozu.dev/ja/kintone/docs/js-api/plugins/kintone-plug-in-proxy/)・[getProxyConfig](https://cybozu.dev/ja/kintone/docs/js-api/plugins/get-config-for-proxy/)・[認証](https://cybozu.dev/ja/kintone/docs/rest-api/overview/authentication/)。

### 秘匿できる範囲

秘匿できるのは値だけで、使えることは隠せない。利用者が開発者ツールから `kintone.plugin.app.proxy` を呼べば、そのトークンの権限でリクエストを送れる。API トークンの権限は必要な操作だけに絞る（設定画面にも、その旨を書く）。

保存する URL を API ごとに絞っても、`.../record.json/../app/form/fields.json` のような URL で前方一致をすり抜けられるかは確かめていない。すり抜けられてもコードでは防げないので、実際の防御はトークンの権限である。

## 保存の構成（両プラグイン共通）

秘密は `setProxyConfig` に、秘密でない目次は `setConfig` に分けて保存する。

| 保存先 | 入れるもの |
| --- | --- |
| `setConfig` | 目次。設定画面に行を出し直すための情報（URL・メソッド・キー名・メモ・トークンを設定したかどうかなど。中身は各プラグインの章）。秘密は入れない |
| `setProxyConfig` | トークン・ヘッダー・本文 |

| 操作 | 振る舞い |
| --- | --- |
| 設定画面の読み込み | 目次を読み、`getProxyConfig` で秘密を読んでフォームに戻す。画面での見せ方はプラグインごとに決める（auto-numbering はパスワードの欄で伏せ字。api-proxy はふだんキーだけを出し、値は編集のダイアログの中でだけ見える） |
| 保存 | 1. 新しい組を `setProxyConfig` で保存する　2. 前回保存した組と `knownKeys` の組のうち、今回無いものを `{}` で上書きする（前回の保存が途中で失敗すると予約キーに記録されないため、保存しうるキーが決まっていれば常に対象にする）　3. 秘密を除いた設定を `setConfig` で保存する。途中で失敗したら `setConfig` は保存せず、保存の失敗として表示する（保存し直せばそろう） |
| エクスポート | 秘密を除いて書き出す |
| インポート | 読み込んだあと、保存済みの秘密のうち URL とメソッドが合うものを埋める |
| リセット | フォームを既定値に戻すだけ。保存したときに、消えた組を `{}` で上書きする |

実装は `kintone-utils` の `definePluginConfig` に渡す `secrets`（`toEntries`・`strip`・`fill`・任意の `knownKeys`）。前回保存した組のキーは、`setConfig` の予約キー `__proxyKeys` に入れる（プロキシ設定は一覧で読めないため）。plugin-shell は、読み込み・インポート・保存・エクスポートでこれを使う。

## auto-numbering

先に作り、同じドメインへの `proxy` が検証用の kintone で動くことを確かめる。

| 項目 | 要件 |
| --- | --- |
| トークンの保存 | `X-Cybozu-API-Token` をプロキシ設定に保存する（前後の空白は除く）。保存先は採番で使う API だけ（GET `records.json`・GET `record.json`・PUT `record.json`）。`/k/v1/` 全体にすると、利用者が開発者ツールから呼ぶほかの API にもトークンが付くため。URL は `kintone.api.url` で作る（ゲストスペースでは `/k/guest/{スペースID}/v1/`）。`setConfig` にはトークンを空で入れ、`common.useApiToken` を入れる |
| 読み込みとインポート | `useApiToken` に関係なく、保存済みのトークンで欄を埋める（トークンの無いファイルをインポートして保存しても、保存済みのトークンを消さないため） |
| 実行 | `useApiToken` なら `kintone.plugin.app.proxy` で、そうでなければ `kintone.api`（セッション）で呼ぶ。理由は auto-numbering の design.md の ADR-005 |
| ゲストスペース | 対応する（URL は `kintone.api.url` が作る）。実機では未確認 |
| 接続先のドメイン | 保存する URL には、設定画面を開いたときのホストが入る。利用者が別のホスト（セキュアアクセスの `.s.cybozu.com` など）から使うと前方一致せず、トークンが付かずに採番が失敗する可能性がある。kintone の一致がホストを含むかは未確認（手元の環境は1つのホストだけ） |
| 旧版の設定 | 版を2に上げる。v1 の `apiToken` はフォームの欄に引き継ぎ、設定画面で保存したときにプロキシ設定へ移す。それまでは、実行画面はセッションで呼び、平文のトークンも `setConfig` に残る。v1 の間に利用者が読めたトークンは、移しても同じ値で使えるので、再生成してから入れ直す |

## api-proxy（汎用プラグイン）

### 目的

JS カスタマイズや他のプラグインが、API トークンなどの秘密を、利用者に値を見せずに使えるようにする。秘密が付くのは、管理者が登録した URL とメソッドの組だけである。

### 守れるもの・守れないもの

登場する人は、アプリの管理者（設定画面を開ける）・アプリの利用者（レコードの画面を開け、開発者ツールで任意の JS を実行できる）・kintone に入れない人。

| | 内容 |
| --- | --- |
| 守れる | 秘密の値の持ち出し（kintone の外や後日に使う）。アプリへのアクセスを外した人の利用（プロキシは、プラグインを入れたアプリの画面からしか呼べない）。ソースコード・エクスポートしたファイル・画面共有・ログからの漏えい |
| 守れない | アプリを開ける利用者は誰でも、保存した組の範囲で、秘密の権限を使える。kintone のトークンは利用者本人の権限とは別に働くので、閲覧の権限が無いレコードでも、トークンで取得すれば応答として読める。呼び出した JS や利用者で絞ることもできない |
| 確かめていない | 前方一致を `..` などですり抜けられるか（[秘匿できる範囲](#秘匿できる範囲)） |

呼び出し元や利用者で絞る必要があるときは、このプラグインの範囲を越える。独自の認証を持つ中継サーバーを使う。

### 使える範囲を決める要素

使える範囲は、次のすべてが重なった部分になる。既定では URL とメソッドで絞らず、トークンの権限に任せる。絞りたいときは、管理者が URL とメソッドを具体的にする。

| 要素 | 決める場所 | このプラグインでの扱い |
| --- | --- | --- |
| トークンの権限（閲覧・追加・編集・削除・アプリ管理） | kintone のアプリの設定 | 最も強い制限。設定画面で、必要な権限だけにし、アプリ管理の権限は付けないよう案内する |
| 対象のアプリ | kintone（トークンはアプリごとに発行される） | なし |
| URL の前方一致 | プロキシ設定 | 管理者が書いた URL のまま保存する。`/k/v1/` と書けば kintone の REST API 全体に、`/k/v1/records.json` と書けばその API だけに付く |
| メソッド | プロキシ設定 | 行ごとに選ぶ（既定は GET・POST・PUT・DELETE のすべて） |
| 本文の値の固定 | プロキシ設定の `data` | POST・PUT で、呼び出し側の本文がオブジェクトのときだけ、保存した値が優先される（例：Slack の投稿先のチャンネル）。GET・DELETE では重複を判定しないので固定できない |
| 呼び出せる画面 | kintone（プラグインを入れたアプリ） | アプリ X からアプリ Y を操作するなら、X のプラグイン設定に Y のトークンを登録する |

制限しないとき（kintone の REST API 全体に4つのメソッドで保存したとき）に、アプリを開ける利用者ができてしまうこと：

| トークンの権限 | できてしまうこと |
| --- | --- |
| 閲覧 | 全レコードを読める（レコードのアクセス権で見えないはずのものも） |
| 追加・編集・削除 | 本人に権限が無くても、レコードを追加・更新・削除できる（記録は Administrator の操作になる） |
| アプリ管理 | アプリの設定やアクセス権を書き換えて、運用環境に反映できる |

### 保存するもの

| 保存先 | 内容 |
| --- | --- |
| プロキシ設定（秘密） | 行の URL と、選んだメソッドごとに1件。値はヘッダーと本文の値 |
| 通常のプラグイン設定（目次） | 行の URL・メソッド・ヘッダーと本文のキー名・本文の値の種類・メモと、保存した組のキー。利用者から見えるので値は入れない |

プラグイン自身は実行画面の処理を持たない。呼び出す側は、このプラグインの ID を書いて `kintone.plugin.app.proxy` を呼ぶ（README と設定画面に例を出す）。

### 接続先タブ

kintone の REST API と外部の API を、同じ形の行で登録する。

| 項目 | 要件 |
| --- | --- |
| 行 | URL・メソッド（複数選べる。既定は4つすべて）・ヘッダー・本文の値（任意）・メモ |
| 並べ方 | 1つの接続先を表の1行にする（列: URL・メソッド・ヘッダー・本文の値・メモ）。行は並べ替えられ、各行の「この下に追加」で直後に追加できる（順番は動作に影響しない）。狭い画面では表を横にスクロールする |
| ヘッダーと本文の値の入力 | ふだんはキーの一覧だけを出す（値は伏せる）。「編集」でダイアログを開き、JSON（`{"キー": 値}`）でまとめて書く。ヘッダーの値は文字、本文の値の種類（文字・数値・真偽）は JSON の値から決まる。値が多くても1つずつ入力せずに済むため |
| 説明の出し方 | 画面に説明文を並べず、見出しの横の ⓘ にカーソルを乗せたときに箇条書きで出す（画面を短くするため） |
| kintone の入力の補助 | 「kintone URL を挿入」ボタン（`{自ドメイン}/k/v1/`。ゲストスペースの ID を入れれば `/k/guest/{ID}/v1/`）。ヘッダーのダイアログの「kintone API トークンを追加」ボタン（キー `X-Cybozu-API-Token`） |
| 複数アプリのトークン | 1つの値にカンマ区切りで書く（kintone の仕様。ルックアップ元のアプリのトークンもここに足す）。9個まで |
| 本文の値の送られ方 | ⓘ で説明する。GET・DELETE はクエリ文字列に足される（呼び出し側の同じキーは消えない）。POST・PUT は、呼び出し側の本文がオブジェクトなら足され、同じキーは保存した値が優先される |
| 検証 | URL は `http://` か `https://` で始まる。メソッドは1つ以上。同じ URL とメソッドの組は、複数の行で重ねられない。キーは空にできず、1つの行の中で重複できない。`X-Cybozu-API-Token` の値は9個まで |
| 注意 | 前方一致が重なる行（例：`/k/v1/` と `/k/v1/records.json`）は、長く一致した行の値が優先されると知らせる（エラーにはしない） |
| 案内 | 絞りたいときは URL を具体的に書き、メソッドを減らす。固定したい値は本文に書く（固定できるのは POST・PUT だけ）。URL・キー・メモは目次に入って利用者から見えるので、秘密を書かない |

### 使い方タブ

権限についての注意（全文。ⓘ に隠さない）、このプラグインの ID、`kintone.plugin.app.proxy` の呼び出し例（kintone のレコードの取得。登録した接続先には合わせない固定の例）を出し、ID と例はコピーできる。設定画面からは proxy を呼べない（使えるのはレコードの画面だけ）ので、試すのはレコードの画面で行う。

## 実機で確かめること

2026-11-23 に auto-numbering で確認済み：

- 同じドメインへの `proxy` で、レコードの取得と更新ができる。保存したトークンで採番できる
- 保存した値が開発者ツールの通信とプラグイン設定（`getConfig`）に現れない
- 設定画面を開き直すと、保存済みのトークンが入っている
- エクスポートしたファイルにトークンが無く、それをインポートしてもトークンが消えない
- 消した組が `{}` の上書きで無効になる（トークンを消して保存し「アプリを更新」すると、proxy は 401 になる。入れ直すと元どおり採番できる）
