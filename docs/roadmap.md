## フェーズ1: アーキテクチャの統一

React の共通コンポーネント（`packages/ui`）と共通ロジック（`packages/kintone-utils`）を使い回して開発効率を上げることが、このリポジトリの目的の一つ。そのために各プラグインの構成を揃える。目標の構成は [architecture.md](./architecture.md)。

1. [x] 3プラグインと `template/` の構成の差分を洗い出す
2. [x] 目標の構成を `architecture.md` にまとめ、合意する
3. [x] kintone の型を、公式の型とイベントの外枠に置き換える（`kintone-utils/src/types/kintone/` を廃止）
4. [x] `template/` を lint・型チェック・CI の対象にし、壊れている箇所を直す
5. [x] 設定画面の骨組みを共有パッケージ（`plugin-shell`）に移し、`template/` を最初の利用者にする
6. [x] 依存関係を最新にする。2026-11-22 に、3プラグインを kintone の実機で確認した（問題なし）。判断の理由は [decisions/tooling.md](./decisions/tooling.md)
7. [x] フィールドを選ぶ部品を共有パッケージに移す（`ui` の `FormAutocomplete`、`plugin-shell` の `FieldSelect`）。既存の6か所は手順8 で置き換える
8. [x] 既存のプラグインを1本ずつ移行する（1プラグイン1PR）。小さい順に age-calculator（2026-11-23 に実機で確認済み）→ field-controller（2026-11-23 に実機で確認済み）→ auto-numbering（2026-11-23 に実機で確認済み）。移行したプラグインからは、骨組みのコピー（`src/config/hooks`・`states`）を消す

## 実機確認の項目

設定画面や実行画面に関わる変更の後（手順8 の各移行など）に、検証用の kintone で確かめる。各プラグインで `pnpm build` のあと `pnpm upload` でアップロードする（アップロードには利用者の承認が要る）。

| 対象               | 確認すること                                                                                                                 |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| アップロード       | kintone に反映される。2回目以降は同じプラグイン ID の更新（`reinstall`）になり、別のプラグインとして増えない                  |
| 設定画面の表示     | タブ・入力欄・フィールドの選択肢・並べ替え・ダイアログの見た目と配置が崩れていない                                           |
| 設定画面の読み込み | 保存済みの設定が表示される。フィールドの一覧が読み込まれる                                                                   |
| 設定画面の操作     | 保存・リセット・インポート・エクスポートで画面が更新される。入力の検証エラーが表示される                                     |
| 実行画面           | age-calculator の年齢計算、field-controller の表示・編集の制御、auto-numbering の採番（レコードの取得と更新）が動く           |
| 対話式のコマンド   | `pnpm run init` と `pnpm gen` の入力が動く。Claude Code の `!` ではキー入力を送れないので、ターミナルで確かめる              |
