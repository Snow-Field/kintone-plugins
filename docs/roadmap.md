## 実機確認の項目

設定画面や実行画面に関わる変更の後に、検証用の kintone で確かめる。変更に関係する行だけでよい。各プラグインで `pnpm build` のあと `pnpm upload` でアップロードする（アップロードには利用者の承認が要る）。

| 対象               | 確認すること                                                                                                                 |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| アップロード       | kintone に反映される。2回目以降は同じプラグイン ID の更新（`reinstall`）になり、別のプラグインとして増えない                  |
| 設定画面の表示     | タブ・入力欄・フィールドの選択肢・並べ替え・ダイアログの見た目と配置が崩れていない                                           |
| 設定画面の読み込み | 保存済みの設定が表示される。フィールドの一覧が読み込まれる                                                                   |
| 設定画面の操作     | 保存・リセット・インポート・エクスポートで画面が更新される。入力の検証エラーが表示される                                     |
| 実行画面           | age-calculator の年齢計算、field-controller の表示・編集の制御、auto-numbering の採番（レコードの取得と更新）が動く           |
| 対話式のコマンド   | `pnpm run init` と `pnpm gen` の入力が動く。Claude Code の `!` ではキー入力を送れないので、ターミナルで確かめる              |

### 先に片付けるもの（共有パッケージ・開発環境）

フェーズ2 で新しいプラグインを作る前に直す。上から順に進める（推奨）。共有パッケージの直しは3プラグインすべてに効くので、実機確認は3本とも行う。

| # | 問題 | 場所 | 推奨の理由 |
| --- | --- | --- | --- |
| 1 | `genkey.js`・`upload.js`・`dotenv.js` が、template と3プラグインの4か所に同じ内容でコピーされている | 各プラグインと template の `scripts/` | 新しいプラグインで5か所目のコピーを作らないため |
| 2 | template の `manifest.json` はプラグイン名と説明が空で、そのままでは zip を作れない。`pnpm gen` で名前を聞いて書き込むかを決める | `template/public/manifest.json`・`scripts/create-plugin.js` | フェーズ2 で `pnpm gen` を使う前に |

### 各プラグインで直すもの（フェーズ3）

| 問題 | 場所 |
| --- | --- |
| auto-numbering で、書式のフィールドのパーツに選んだフィールドが空のまま保存すると、レコードは保存され、その後の採番が失敗して番号の無いレコードが残る（失敗の理由は表示する）。保存の前（submit イベント）に止めるかを決める | auto-numbering の `shared/handlers` |
| auto-numbering で期間ごとにリセットするとき、同じ期間の採番値は新しい順に500件までしか見ない。それより多いと最大の連番を見落とし、重複の再試行（最大10回）で採番に失敗することがある | auto-numbering の `shared/api/serial.ts` |
| auto-numbering は API トークンをプラグイン設定に平文で保存している。プラグイン設定はアプリを使う全員がブラウザから読めるため、トークンが漏れる。フェーズ2 のトークン秘匿プラグイン（プロキシ設定を使う）で解消する | auto-numbering |
| field-controller の条件のフィールドがアプリから消えていると、配列の値（「含む」で選んだ値）が文字の入力欄に「x,y」のように出る。フィールドを選び直すと値は空になる | field-controller の `ConditionRow.tsx` |
